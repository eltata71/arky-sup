# Diagram Quality Gate

**Status:** Shipped (May 2026 audit follow-up)
**Owner:** Diagram pipeline team

## Problem

Diagrams generated by Arky 10 routinely scored 60–80/100 on the 10-dimension
rubric (`services/diagramQualityService.ts`). The score badge often showed
"Crítico" or "Mejorable", and reaching "World Class" (≥ 90) was inconsistent
even when the project context was rich enough to support it.

Root causes identified:

1. **Parser bias**: `mermaidToIR.ts` defaulted unknown nodes to `kind: "Component"`,
   which the scoring service explicitly excluded from `claridadSemantica`.
2. **No metadata**: legacy artifacts had no `title`, `audience`, `theme`,
   `density`, or `narrative`, leaving easy points on the table for
   `narrativa`, `preparacionEjecutiva`, and `mantenibilidadPipeline`.
3. **No structural auto-repair**: orphan nodes, empty/generic edge labels,
   missing groups and id-equal labels stayed in the IR forever.
4. **No quality gate**: nothing systematically tried to lift a low-scoring
   diagram before saving it. The only auto-repair (`services/diagram/autoRepair.ts`)
   handled architectural violations, not lint issues.
5. **UI lacked actionable signal**: the panel listed issues without grouping
   by severity, dimensions used camelCase identifiers, the "Crítico" label
   was misread as project-level criticality, and there was no "Auto-mejorar"
   shortcut.
6. **Mermaid parser blind spots**: inline label syntax (`A -- label --> B`,
   `A -. label .-> B`), thick equals (`A === B`), async sequence operators
   (`-)`, `--)`), and `<<choice>>` pseudo-states were either ignored or
   miscategorised.

## Solution

### 1. `services/diagram/qualityRepair.ts` (new)

A deterministic, lint-driven repair function that:

- Drops dangling edges (broken refs).
- Normalises unstable IDs (UUID/timestamp → `kebab-case`).
- Reclassifies node kinds to the canonical taxonomy (`person`, `system`,
  `gateway`, `data`, `messaging`, `external`, `service`, `process`, `generic`).
- Humanises labels equal to the id, fills empty labels, truncates labels > 32
  chars.
- Fills missing node descriptions with a role-aware sentence.
- Replaces empty/generic edge labels (`data`, `call`, `connects`…) with verb
  phrases derived from the source/target roles (`"Solicita servicio"`,
  `"Publica evento al broker"`).
- Reconnects orphan nodes to the busiest sibling (preferring a different
  semantic role for meaningful flow).
- Synthesises group buckets per role when ≥ 5 ungrouped nodes exist.
- Fills missing metadata (`title`, `audience`, `theme`, `density`,
  `generatedAt`, `narrative`) with sensible defaults derived from the IR
  topology and artifact context.
- Records every change in `metadata.repairHistory`.

### 2. `services/diagram/qualityGate.ts` (new)

An iterative orchestrator that runs:

1. `detectArchitecturalViolations` → `autoRepairIR` (architectural fixes).
2. `autoRepairDiagramIR` (structural / lint-driven fixes).
3. `analyzeDiagramQuality` (re-score).

Up to N passes (default 3) while the score keeps improving and changes
remain. Returns the best snapshot seen, the final report, and a flat
changelog the UI can surface.

### 3. Pipeline wiring

- **Generation** (`services/geminiService.ts::generateAndRefineDiagramIR`):
  the deterministic gate replaces the previous `autoRepairIR`-only step,
  guaranteeing the post-repair IR has clean metadata, no orphans, and
  verb-driven labels before the AI critique pass.
- **Render** (`services/diagram/resolveRenderableDiagram.ts`): the gate
  also runs at render time for legacy artifacts (Mermaid-only, no
  `artifact.ir`) so the score badge reflects the best deterministic
  version even before the user clicks "Auto-mejorar". Skipped when the
  persisted IR already declares a quality score ≥ 90 to avoid redundant work.

### 4. Strengthened Mermaid parser (`services/diagram/mermaidToIR.ts`)

New syntactic forms supported:

- Inline-label flowchart: `A -- label --> B`, `A -. label .-> B`,
  `A == label ==> B`.
- Thick equals link: `A === B` (mapped to `data-flow`).
- Sequence async operators: `-)`, `--)`.
- State pseudo-states: `decide <<choice>>` / `<<fork>>` / `<<join>>` →
  diamond shape.
- Composite states: `state Foo { ... }` declared as `tab-box`.
- Default kind for unknown nodes is now `service` (canonical), not
  `Component`.

### 5. Specialised prompts (`services/ai/prompts/diagramPrompts.ts`)

`buildArchitecturalConstraints` now branches per type:

| Diagram type | Key guardrails |
|---|---|
| C4 Context | ≤ 8 nodes, only actors + system + externals, no internals. |
| C4 Container | TECH on every container, PROTOCOL on every Rel, no UI→DB direct. |
| C4 Component | One container in scope, single clear responsibility per component. |
| C4 Deployment | Cloud vs on-prem, technology per node, Container_Instance refs. |
| Sequence | Pre-declare participants, async with `-)`/`--)`, group via rect/alt/loop. |
| ERD | Business-friendly names, PK/FK, explicit cardinality, verb-named relations. |
| State | Initial/terminal states, reachability, event-named transitions, choice/fork. |
| Gantt | Sections per capability, milestones, realistic durations, parallelism. |
| Graph / VSM / BPMN | Verb labels, no orphans, swimlanes for actors, lead/process/wait time. |

### 6. Score UI (`components/ArtifactCanvas.tsx`)

- **Friendly labels**: dimension keys mapped to Spanish (`Claridad
  semántica`, `Preparación ejecutiva`, …).
- **Probable cause**: highlights the lowest-scoring dimension as the
  primary cause when score < 90.
- **Severity grouping**: issues grouped by `Críticos / Altos / Medios /
  Bajos` instead of a flat list.
- **Action buttons**: `Auto-mejorar diagrama` (runs the deterministic
  gate and persists) and `Regenerar World Class` (prompts the user to
  trigger a fresh generation that goes through the full gate).
- **Badge text**: `Crítico` → `No listo para presentación` to avoid
  misreading the score as project-level criticality.

### 7. Export preflight (`services/diagramQualityService.ts`)

- New `orphans` check fails the gate when orphan nodes exist.
- Quality bands tightened: `< 70` fail, `70–89` warn (recommend
  Auto-mejorar), `≥ 90` pass.
- The `integrity` check now also fails on `EDGE_INVALID_REFERENCE`.

## Testing

New test files under `__tests__/diagram/`:

- `qualityRepair.test.ts` — orphan reconnection, empty/generic edge labels,
  id humanisation, dangling edge removal, group synthesis, metadata
  filling, repair history.
- `qualityGate.test.ts` — full pipeline lifts low-quality IR over 90,
  no-op when target already met, plateau behaviour for empty IR.
- `mermaidToIRExtended.test.ts` — inline labels, thick equals, async
  sequence operators, choice pseudo-state, canonical kind classification.
- `diagramPreflight.world-class.test.ts` — pass/warn/fail bands and the
  new orphans check.

The test suite passes 280/280.

## Residual debt / future work

- The `Regenerar World Class` button currently shows an `alert()` because
  the regeneration entry point lives in `Workspace.tsx` and would require
  threading a callback through `ArtifactCanvas` props. Wiring it through is
  ~30 lines and could be done in a follow-up.
- The IR-direct generator (`VITE_DIAGRAM_GENERATOR=ir-direct`) and
  refinement (`VITE_DIAGRAM_REFINEMENT=true`) flags are still opt-in. The
  quality gate is on by default in both legacy and IR-direct paths, so a
  future audit could promote the ir-direct + refinement combo to default.
- The render-time gate skips when `artifact.ir.metadata.qualityReview.score
  >= 90`. Older persisted IRs lack this field; their gate will run on every
  read until they're touched again. A one-time persistence migration could
  back-fill the qualityReview block.
- The `Auto-mejorar` button persists the new IR but does NOT update Mermaid
  content for C4 artifacts (the serializer emits flowchart only). C4
  round-tripping remains a known limitation.
